# bun-http-sqlite

A neoc HTTP server backed by `bun:sqlite`, built on **ports & adapters**: neoc
owns the contracts, the host adapts.

- `GET /notes` (or any path) — list all notes (via the DAO's `list_notes`)
- `GET /add/<text>` — insert a note (via the DAO's `add_note`)

## How it's wired

The app is written in neoc and declares the **ports** it depends on as `ext`
blocks, in neoc's own types (`Result`, `Option`, `SqlValue`, `fn`):

- **`src/main/neoc/main.neoc`** — the app. It declares three ports —
  `db` (`execute` / `query` over `[SqlValue]`), `http` (`serve`), and `text`
  (`strip_prefix` / `from_number`) — each an `ext mod` pointing at the adapter:
  ```neoc
  #[extern(path = "../ts/adapter.ts")]
  mod db {
      fn execute(sql: string, params: [SqlValue]) -> Result<number, string>;
      fn query(sql: string, params: [SqlValue]) -> Result<[[SqlValue]], string>;
  }
  ```
  A zero-field `struct Db` implements the autosql `SqlExecutor` trait by
  forwarding to the `db` port. neoc never holds a host handle, never sees
  `Unknown`, and does no string interpolation.
- **`src/main/ts/adapter.ts`** — the host adapter. It `implements` every port
  over `bun:sqlite` and `Bun.serve`, typed against neoc's **emitted**
  declarations (`../js/neoc-lib`, `../js/autosql/ports`). The neoc→TS projection
  is total, so the adapter's TS types line up exactly with the runtime values
  neoc passes — the boundary is lossless and a `match` round-trips. Parameters
  are **bound natively** (no interpolation); result cells are tagged into
  `SqlValue`; the one `bun:sqlite` `Database` lives here and nowhere else.
- **`src/main/neoc/autosql/`** — generated by `neoc autosql` from
  `src/main/sql/{ddl,dml}`: the `SqlValue` enum + `SqlExecutor` trait, the typed
  row structs, and `migrate` / `list_notes` / `add_note`. Regenerate with
  `bun run gen:sql`.

The direction is the point: nothing imports a host module's types *into* neoc.
The adapter hides `bun:sqlite` behind neoc-authored ports, so there is no
reverse-engineered `types.neoc` and no `autots` (retired — see
`tasks/ts-interop-inversion.md`).

## Run

```sh
bun run build    # gen:sql -> neoc build --target js (emits src/main/js/)
bun run start    # starts the server on http://localhost:38573
```

```sh
curl localhost:38573/notes          # 1:hello | 2:world |
curl localhost:38573/add/from-neoc  # added: from-neoc
curl localhost:38573/notes          # 1:hello | 2:world | 3:from-neoc |
```

The emitted JS is idiomatic ESM — `db.execute(...)`, `http.serve(...)`,
`import * as db from "../ts/adapter.ts"` — and the adapter is plain TypeScript
implementing the ports.
