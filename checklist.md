# Sweeping language-feature checklist

Run yourself by this when adding or changing a **language feature** in neoc — a
new construct, a type-system capability, a runtime-semantics change. Not for a
bug fix or a tooling-only change.

**Three cardinal rules** (everything below serves them):

1. **Spec first.** `lang/` is canonical; the spec wins over the impl. Write/amend
   the spec, then make the code match it.
2. **Stages move together.** A feature touches grammar → AST → parser → types →
   *both* codegens → conformance. A node the parser produces but no emitter
   handles — or an emitter for a node the checker never sees — is a desync bug.
   **Never land a half-threaded feature.**
3. **No host-language leaks.** Every user-visible string (diagnostics, hover,
   errors) speaks neoc — `number`, `struct`, `match arm`, `Result<T,E>` — never
   Rust/tree-sitter/`thiserror` internals. `ext`/`extern "<host>"` is the only seam.

---

## 0. Scope & design

- [ ] Decide the construct end-to-end *before* coding: surface syntax, static
  rules, runtime lowering on **every** target. Write it in `tasks/<feature>.md`.
- [ ] Confirm it fits neoc's premise (Rust minus lifetimes/ownership; GC).
- [ ] Identify the drift points if it introduces a typed runtime value (see #54
  runtime enforcement) — where untyped→typed ingress must be validated.

## 1. Spec (`lang/`) — do this first

- [ ] `SYNTAX.md` — EBNF for the new grammar (both the §1–9 prose form *and* the
  appendix collected grammar; keep them consistent).
- [ ] `STATIC.md` — name resolution, typing rules, well-formedness; any new
  diagnostics, in neoc terms.
- [ ] `DYNAMIC.md` — the lowering table entry: neoc construct → emitted code, per
  target. Include any runtime validator/enforcement shape.
- [ ] `LEXICAL.md` / `NOTATION.md` — only if new tokens or meta-notation.
- [ ] `RATIONALE.md` — if it's a notable design choice worth recording.
- [ ] Plan the `CONFORMANCE/` cases (see §10) as part of the spec.

## 2. Grammar (`crates/neoc-grammar/tree-sitter-neoc` — a submodule)

- [ ] Edit `grammar.js`. Mind LR/GLR conflicts; resolve with `prec`/declared
  `conflicts`, not by loosening rules into ambiguity.
- [ ] `tree-sitter generate` (needs the `tree-sitter` CLI, ABI 15). Iterate until
  it generates clean.
- [ ] **Keep `src/node-types.json` stable** where possible — hide helper rules
  (`_name`) and `alias(...)` new variants back to existing node kinds, so the
  AST adapter (`neoc-parser`) needs no change. A new public node kind = adapter
  work; weigh it.
- [ ] Normalise `src/parser.c`'s header to the committed form
  `/* Automatically @generated by tree-sitter */` (strip the CLI version).
- [ ] `git checkout src/tree_sitter/array.h` — don't commit the CLI's vendored
  runtime header churn.
- [ ] `touch crates/neoc-grammar/build.rs` so the cc build picks up the new
  `parser.c`.
- [ ] Commit **in the submodule** on a branch, push it, **then** bump the
  submodule pointer in the neoc superproject. The submodule is a separate repo;
  do not orphan a commit the superproject history references.

## 3. AST (`crates/neoc-ast`)

- [ ] Add/extend nodes as pure data (`Debug, Clone, PartialEq`).
- [ ] `Span`'s `PartialEq` is **always-true** by design — adding a `span` to a
  node does **not** churn AST-equality goldens. Use it freely for binding/decl
  sites. (Do *not* key a `HashMap` on `Span` — all spans compare equal; key on
  `(start, end)`.)
- [ ] `neoc-ast` is a **wasm-leaf** crate — keep it host-free (no `std::fs`, no
  deps that don't cross-compile to `wasm32`).
- [ ] Update `crates/neoc-ast` unit tests.

## 4. Parser (`crates/neoc-parser`)

- [ ] `walk_<construct>` for each new node; thread spans via `span_of`.
- [ ] Surface syntax errors anywhere in the tree (ERROR/MISSING nodes), not just
  top-level — `collect_syntax_errors` sweeps when `root.has_error()`.
- [ ] Any parse diagnostic is **neoc-shaped**, never a raw tree-sitter message.
- [ ] Update `crates/neoc-parser/tests/adapter.rs` (assert the typed AST).

## 5. Types (`crates/neoc-types`)

- [ ] `collect.rs` — record the new declaration into the `SymbolTable` (and its
  `pub` visibility set if cross-module-visible).
- [ ] `infer.rs` — inference + well-formedness + new diagnostics (neoc-shaped).
- [ ] `elaborate.rs` — any construct that lowers in terms of another.
- [ ] `resolve.rs` — if it introduces bindings/uses, feed the scope-aware
  resolution map (binding kind + def span; record uses at the resolution site).
- [ ] Honour the **`_with_table` variants** for cross-module: a feature visible
  across files must work through `check_with_table` / `elaborate_with_table`,
  not only the single-file `check` / `elaborate`.
- [ ] Recording flags (`record_types`, `record_resolution`) stay **opt-in** so
  the compile path pays nothing.

## 6. Codegen — **BOTH targets** (`neoc-codegen-lua` *and* `neoc-codegen-js`)

- [ ] `emit_<construct>` in **each** backend. A construct emitted on Lua but not
  JS (or vice-versa) is a desync — both, or neither.
- [ ] Lua: methods via metatable (`recv:method(...)`), structs tagged
  `__struct` + `setmetatable`. JS: the `__m`/`__call` dispatch keyed on
  `__struct`/`__enum`. Match the existing idioms.
- [ ] If the feature creates a typed runtime value, emit the #54 validator at the
  drift points (construction, mutation, untyped ingress) — deep, always-on.
- [ ] Emitters are **pure** (`&Node -> String`); no mutation of inputs.
- [ ] (No Python backend exists yet — note it if the spec promises three targets.)
- [ ] Update `tests/emit.rs` goldens in each codegen crate.

## 7. Runtime (`crates/neoc-vm`) — only if it needs host support

- [ ] New host capability comes through an `ext`/`extern` declaration — no magic
  globals. The *form* is the language's; the *contents* are the runtime's.
- [ ] `cargo run -p neoc -- emit-headers --out crates/neoc-vm/src/lua` if headers
  change. Keep the sandbox surface curated.

## 8. Derives / macros (`crates/neoc-macros`)

- [ ] If the feature is a new trait or interacts with `#[derive(...)]`, decide how
  derives relate (the four built-ins are trait impls synthesised at codegen).

## 9. Tooling

- [ ] **Formatter (`neoc-fmt`)** — new syntax must format and round-trip.
- [ ] **LSP (`neoc-lsp`)** — the construct should work in every relevant handler:
  diagnostics, document/workspace symbols, goto/type-def/impl, references,
  rename, hover, completion (+ resolve), semantic tokens, folding, inlay hints,
  call hierarchy, document highlight, code actions. Handlers stay **thin
  consumers** of `neoc-types`/CST — no parallel resolver in the LSP.
- [ ] New lints belong in the `neoc-lsp` lint registry (they are **warnings**,
  tested in `neoc-lsp` — *not* in `CONFORMANCE/static`, which asserts compiler
  *errors*).
- [ ] Add `.feature` cucumber specs in `tooling/ide/` for new editor behaviour.

## 10. Conformance (`lang/CONFORMANCE`) — the feature isn't done without it

- [ ] `syntax/` — an accept `.neoc` and a `.reject` + `.reject.expected` for the
  failure mode. Driven by `crates/neoc-compiler/tests/conformance_syntax.rs`.
- [ ] `static/` — `.neoc` + `.diagnostics` pairs (positive *and* the rejection).
  Driven by `conformance_static.rs`.
- [ ] `dynamic/` — `.neoc` + `.lua` + `.js` (+ `.stdout`/`.rs`) — the construct
  runs and produces the same result on each target. Driven by
  `conformance_dynamic.rs`. A wrong-type value must be **rejected at runtime** on
  every target (per #54).

## 11. Public API (`neoc-compiler/src/lib.rs`)

- [ ] Re-export anything new that's public surface. Anything not re-exported is
  private and may change without a bump.
- [ ] A breaking API change → `feat(...)!` + a `BREAKING CHANGE:` footer.

## 12. Gates — all green before push (CI mirrors these)

- [ ] `cargo test --workspace`
- [ ] `RUSTFLAGS="-D warnings" cargo clippy --workspace --all-targets`
- [ ] `cargo fmt --check`
- [ ] `cargo check --target wasm32-unknown-unknown -p neoc-ast -p neoc-macros -p neoc-codegen-lua` (wasm leaf gate)
- [ ] If the runtime was touched: `cargo run -p neoc -- run 'crates/neoc/tests/**/*.test.luau'`
- [ ] Build the realistic demo — `packages/bun-http-sqlite/` — and confirm it still
  transpiles (and runs) cleanly; it catches integration regressions unit tests miss.

## 13. Desync sweep — confirm the chain is whole

- [ ] grammar emits the node → parser walks it → AST carries it → checker types it
  → **both** codegens lower it → conformance pins it on every target. No gap.
- [ ] Every user-visible string still speaks neoc (re-read diagnostics/hover).
- [ ] Spec and impl agree; where they diverged, the **spec won** and the impl was
  fixed.

## 14. Process & commit

- [ ] Run the `change-review` skill on the staged diff before committing.
- [ ] Conventional Commits (release-plz reads them); one logical change per commit.
- [ ] Update the `tasks/` doc; mark the slice done with the commit ref.
- [ ] Submodule pushed *before* the pointer-bump commit.
- [ ] After push, gate the pipeline once: `glab ci status --live` (600000ms timeout).
- [ ] Do **not** `git add -A` — `.claude/worktrees/` is an embedded repo; stage
  explicit paths.

## Gotchas learned the hard way

- `Span::eq` is always-true — safe for adding spans, fatal for `HashMap<Span,_>`.
- Codegen tags are `_struct` historically; the standard is **double underscore**.
- Generic bounds are *parsed but unread* by the checker today — `<T: Trait>` is
  documentation until bound-resolution lands.
- Binding/member *name* sites (`Param::Named`, `Pattern::Binding`, struct fields,
  method names) historically lacked spans — adding them is mechanical (≈35 sites)
  but touches parser + both codegens.
- Lints are LSP-layer warnings, not compiler diagnostics — don't put them in
  `CONFORMANCE/static`.
- A first attempt that type-checks can still be wrong (silent over-acceptance) —
  test the *reject* path, not just the accept path.
