# `match` arm comma after a block body

- **Status:** deferred (needs a grammar refactor; first attempt reverted)
- **Priority:** P3
- **Repo:** grammar lives in the `tree-sitter-neoc` submodule

## The gap

A `match` arm whose value is a block-bounded form — `{ … }`, `if`, `match`,
`while`, `for`, `loop` — currently still needs a trailing comma before the next
arm:

```neoc
match x {
    0 => {
        let y = 1
        y
    },          // <- this comma should be optional, as in Rust
    _ => 2
}
```

Without the comma the following arm is swallowed and the `match` reads as
non-exhaustive. `SYNTAX.md` §6.3 already writes the comma as optional
(`MatchArm ::= Pattern [ "if" Expr ] "=>" Expr [ "," ]`), so the grammar is
stricter than the spec — the grammar is the bug.

## Why the first attempt was reverted (commit 12e5830 → 9fc254f)

The attempt split `match_arm` into a block-ending branch (comma optional) and a
comma-required branch, and resolved the resulting LR conflict with
`prec.dynamic` + a declared `conflicts` entry. That made the comma effectively
optional for **every** arm, which reintroduced the classic arm-boundary
ambiguity:

```neoc
match x {
    0 => g          // value parsed as the call `g(1)` ...
    (1) => 2        // ... so this arm and the `0` arm silently vanished
    _ => 3
}
```

Only `_ => 3` survived, with no diagnostic. Silent arm-dropping is worse than
the original (which simply required the comma). The dynamic-precedence /
declared-conflict route cannot enforce "comma required for a non-block arm".

## The correct fix

Mirror tree-sitter-rust: maintain a parallel **non-block** expression category
so a non-block arm's value cannot extend across the arm boundary, and the comma
is genuinely required for it.

- Introduce `_expression_ending_with_block` (block, `if`, `match`, `while`,
  `for`, `loop`) and route those forms *only* through it — remove them from the
  plain `_expr_no_assign` choice.
- A `match_arm` (non-final) is then
  `choice(seq(value: _expr_not_ending_with_block, ','), value: _expr_ending_with_block)`,
  with the block branch carrying no comma slot (a trailing comma on a block arm
  is consumed as an empty separator / handled by the final-arm rule).
- The final arm keeps an optional comma for any value.

The blast radius is the whole expression grammar: every context that takes an
expression (let value, return, call arg, binary operand, `if`/`while`
condition via `_cond_expr`) must still accept a block-ending expression where it
does today (`let x = if c { a } else { b }`). Each needs auditing and a
conformance case. This is why it is its own task, not a drive-by.

## Acceptance

- `=> { … }` / `=> if … { … }` arms parse with **no** trailing comma.
- `=> expr` (non-block) without a comma is **rejected** (no silent arm drop) —
  add a `.reject` conformance case for `0 => g` newline `(1) => 2`.
- Existing comma-terminated arms still parse.
- `node-types.json` stays stable (alias the final arm; hide the helper rules) so
  the AST adapter needs no change.
- Regenerate `src/parser.c` with `tree-sitter generate` (needs the
  `tree-sitter-cli`, ABI 15); normalise the header comment to the committed
  `/* Automatically @generated by tree-sitter */` form; bump the submodule
  pointer.

## Loose end from the reverted attempt

The grammar branch `feat/match-block-arm-optional-comma` (commit `95ac7cb`) was
pushed to the `tree-sitter-neoc` remote and is now unreferenced. It can be
deleted once this work lands.
